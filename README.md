# Aca-Schedule Web App 開発ドキュメント

## 1. プロジェクト概要

アカペラサークルのライブイベントにおける**本番およびリハーサル**のタイムスケジュール作成を、効率化・自動化し、ヒューマンエラーをなくすためのウェブアプリケーション。

### 主な特徴
- 直感的なUIによるタイムテーブル編集
- 複雑なイベント構成（複数日、クール分け、リハーサル）への対応
- スケジュール作成上のミスを未然に防ぐ、リアルタイム制約チェック機能

---

## 2. UI/UX 設計思想

### ワークフロー
作業フェーズを**「①バンド管理モード」**と**「②タイムテーブル編集モード」**に明確に分離する。ユーザーはまず全バンド情報を登録し、その後スケジューリングに集中する。

| モード | 目的 |
| :--- | :--- |
| **バンド管理モード** | タイムテーブル作成の「材料」となる、全てのバンド関連情報を網羅的に登録・管理する。 |
| **タイムテーブル編集モード** | 登録した情報を元に、タイムスケジュールをパズルのように組む作業に集中する。 |

### テーブル表示
- **アプリ画面上:** ヘッダー行が画面上部に追従する**「固定（スティッキー）ヘッダー」**を採用。
- **エクスポート時:** PDF/画像として出力する際は、クールやページの区切りでヘッダーが**繰り返し印刷**されるレイアウトを採用。

## 3. 開発環境・技術スタック

| カテゴリ | 使用技術・要件 |
| :--- | :--- |
| **言語・フレームワーク** | TypeScript, React, Vite |
| **バックエンド/DB** | Firebase (Firestore) |
| **ソースコード管理** | GitHub |
| **ホスティング/デプロイ** | Vercel（自動でHTTPS化） |
| **主要ライブラリ** | `firebase`, ドラッグ＆ドロップライブラリ (例: `dnd-kit`) |

## 4. 開発ロードマップ

### v0.1: 最小構成の基盤構築
- **🎯 ゴール:** プロジェクトの土台を固め、アプリケーションの骨格を完成させる。ユーザーがイベントを作成し、アプリの基本画面が表示される状態を目指す。
- **⭐ 主要機能:**
    - プロジェクトセットアップ: Vite + React + TypeScript の開発環境を構築し、GitHubとVercelを連携させる。
    - Firebase連携: Firebaseプロジェクトを作成し、Firestoreデータベースへの基本的な接続を確立する。
    - イベント作成ウィザード: アプリの初回利用時に、イベントの必須情報（イベント名、開催日、リハーサル形式など）を入力し、新しいイベントデータを作成する機能を実装する。
    - UIシェル（骨格）: アプリ全体のヘッダーと、中身は空でも機能するトップレベルのナビゲーション（`[ バンド管理 ]` / `[ タイムテーブル編集 ]`）を配置する。

### v0.2: バンド管理モードの完成
- **🎯 ゴール:** タイムテーブル作成の「材料」となる、全てのバンド関連情報を登録・管理できるデータ入力機能を完成させる。
- **⭐ 主要機能:**
    - バンド管理UI: スプレッドシートのような一覧形式でバンドを管理するUIを構築する。
    - バンド情報登録: バンドの基本情報（名称、出演回数）を追加・編集・削除できる機能を実装する。
    - 詳細情報登録: メンバー入力（サジェスト機能付き）、出演可能時間帯（グリッドUI）を設定できるようにする。

### v0.3: 基本タイムテーブル編集モード
- **🎯 ゴール:** 登録したバンド情報を使い、ドラッグ＆ドロップで基本的なタイムテーブルを組み立てるという、アプリの中心的な体験を実現する。
- **⭐ 主要機能:**
    - 編集モードUI: 3ペイン構成（左：ナビ、中央：タイムテーブル、右：バンドバンク）のUIを構築する。
    - バンドバンク: 右ペインに、v0.2で登録したバンドを「未配置バンド」として一覧表示する。
    - タイムテーブル描画: 中央ペインに、まずは単一の日のシンプルなリストとしてタイムテーブルを表示し、時刻を自動計算するロジックを実装する。
    - ドラッグ＆ドロップ: バンドバンクからタイムテーブルへバンドを配置し、タイムテーブル内で順番を入れ替えるインタラクションを実装する。

### v0.4: 高度な構造化とリハーサル対応
- **🎯 ゴール:** 複数日開催やクール分け、リハーサルといった、実際の複雑なイベント運営に対応するための構造的な機能を実装する。
- **⭐ 主要機能:**
    - クール設定機能: 各日のクール数を設定すると、タイムテーブル上に空の「クール枠」が表示され、その中にバンドを配置できるようにする。クール番号は日付をまたいで連番になる。
    - 複数日対応: 複数日のイベントをタブで切り替えられるUIを実装する。
    - リハーサル/本番切り替え: `[ 本番用 ]`と`[ リハ用 ]`のタブを実装し、それぞれで独立したタイムテーブルを編集できるようにする。

### v1.0: 制約チェックと公開バージョン
- **🎯 ゴール:** アプリに「知性」を与え、ヒューマンエラーを自動で防ぐ警告機能をすべて搭載する。これが**最初の公式リリースバージョン**となる。
- **⭐ 主要機能:**
    - v0.4までの全機能
    - 制約チェックと警告表示: タイムテーブル編集モードで、3つの制約チェック（出演可能時間帯の超過、クール内重複、出演者重複）をリアルタイムで行い、問題のある箇所をハイライトやアイコンで表示する。

### v1.1: 共有とエクスポート
- **🎯 ゴール:** アプリ内で完成させたタイムテーブルを、URLやファイルとして外部に出力し、関係者全員と共有できるようにする。
- **⭐ 主要機能:**
    - 共有URL発行: 閲覧専用のURLを生成する。共有時に表示形式（シンプル/詳細）を選択できる。
    - PDF/画像エクスポート: タイムテーブルをファイルとして書き出す。クールやページの区切りでヘッダーが繰り返し挿入されるレイアウトを実装する。

### v2.0: 長期利用と効率化
- **🎯 ゴール:** ログイン機能を導入し、繰り返し利用するユーザーの作業効率を劇的に向上させるためのパワーユーザー向け機能を追加する。
- **⭐ 主要機能:**
    - ログイン機能: ユーザーアカウントを作成し、個人のデータを安全に管理するための基盤を実装する。
    - テンプレート機能: 作成したイベントの構成をテンプレートとして保存し、次回のイベント作成時に呼び出せるようにする。
    - 過去イベント閲覧: ログイン中のユーザーが過去に作成したイベントを一覧表示し、簡単に切り替えて閲覧できるようにする。
    - 高度な設定: カスタム項目管理、プリセット時間設定などを実装する。

## 5. 機能要件定義書

### F-01: イベント管理
- **イベント作成:** ウィザード形式で「イベント名」「開催年」「会場名」「目標」などを設定する。
- **開催日設定:** カレンダーUIを使い、**本番の開催日を複数選択**できる（**連続日とは限らない**）。
- **パスワード設定:** イベント作成時に、そのイベントを編集するための簡易的なパスワードを設定する（F-09参照）。
- **URL発行:** 作成完了後、イベント固有の編集URL（例: `/events/[ID]`）がユーザーに提示される。

### F-02: バンド管理モード
- **UI:** スプレッドシートのような一覧形式。
- **基本情報:** 「バンド名」を登録・編集できる。
- **演奏時間:** 各バンドの**演奏時間（分単位）を設定**できる。F-05で定義された「演奏時間候補」をプリセットとして利用できる。
- **出演回数:** 各バンドの出演回数を設定できる（個別・一括）。
- **メンバー:** 各バンドの出演メンバー名を入力できる（入力候補のサジェスト機能付き）。
- **出演可能時間帯:** バンドごとに、F-01で設定された各開催日に対して、出演可能時間帯をグリッドUIで設定できる。

### F-03: タイムテーブル編集モード
- **UI:** 3ペイン構成。中央のワークスペースには、「本番用/リハ用」タブと、日別のタブが配置される。
- **バンドバンク:** 右ペインに、未配置バンドを一覧表示。出演回数カウンター（例: 1/2）付き。
- **ドラッグ＆ドロップ:** バンドバンクからタイムテーブルへバンドを配置・並び替えする。
- **時刻自動計算:** 全項目の開始・終了時刻をリアルタイムで自動再計算する。
- **カスタムイベント:** 「休憩」「MC」などをタイムラインに挿入できる。

### F-04: 構造化機能（クール）
- 各日のタイムテーブルで、その日に設ける「クール」の数を設定する。
- 設定された数の空の「クール枠」が表示され、その中にバンドを配置する。
- クール数は後からでも変更可能（0も可）。
- **クール番号は日付をまたいでも連番**となる。

### F-05: 時間設定
- バンドごとの**演奏時間はバンド管理モード(F-02)で設定**される。
- バンド間やクール間に、個別の転換時間を任意で設定できる。
- **演奏時間候補:** よく使う演奏時間を「プリセットボタン」として利用できる（定義はF-11で行う）。

### F-06: 制約チェック
- 以下の制約に違反した場合、該当行をハイライトし、アイコンとツールチップで警告する。
  1. **出演可能時間帯の超過（優先度: 高）**
  2. **同一クール内での同一バンドの重複配置（優先度: 中）**
  3. **出演者の連続出演（優先度: 低）**

### F-07: カスタム項目（自由列）
- 項目作成時に、**「バンドごと」か「クールごと」かを選択**する。
- データ入力はバンド管理モードで行う。
- タイムテーブル表示時、固定列（開始時刻、時間、名称）の右側に、**ユーザーが作成した順**で自由列が追加される。

### F-08: リハーサルスケジュール管理
- **形式選択:** イベント作成時に「リハーサル日」か「当日リハ」から選択（混在不可）。
- **リハーサル日設定:** 「リハーサル日」を選択した場合、カレンダーUIからリハーサル日を複数選択できる（**非連続可**）。
- **リハーサル時間:** 全バンドで共通のリハーサル時間（分単位）を1つ設定する。各バンドで個別のリハーサル時間を設定することはできない。
- **当日リハ時間枠:** 「当日リハ」の場合、各本番日に対してリハーサルを行う時間帯を設定でき、超過した場合は警告を表示する。
- **UI:** 「タイムテーブル編集モード」内で「本番用/リハ用」をタブで切り替える。
- **編集:** 本番同様、クール分けやドラッグ＆ドロップで編集する。ただし、各バンドは1回しか配置できない。
- **リスト連携:** 「当日リハ」の場合、その日の**本番タイムテーブルに配置されたバンド**が、その日の**リハーサル用のバンドバンクに自動で表示**される。

### F-09: アクセス管理
- **ゲストモード（v2.0まで）:** イベント固有のURLにアクセスした際、編集画面の前に**パスワード入力画面**を表示する。
- **補足:** このゲストモードは、v2.0で本格的なログイン機能が実装されるまでの一時的な機能であり、**ログイン機能実装後は不要**となる。

### F-10: 共有とエクスポート
- 閲覧専用の一意なURLを生成できる（シンプル/詳細表示を選択可）。
- タイムテーブルをPDFや画像ファイルとしてダウンロードできる。

### F-11: イベント設定
- **UI:** アプリ全体のヘッダーにある設定アイコン（⚙️）からモーダルウィンドウで開く。
- **プリセット時間設定:** そのイベントでよく使う演奏時間をユーザーが自由に設定・変更できる。
- **カスタム項目定義:** F-07で利用するカスタム項目（自由列）の定義（名称、種類）を管理する。

### F-12: 長期利用向け機能（v2.0）
- **ログイン機能:** ユーザーアカウントを作成し、個人のデータを安全に管理する。
- **テンプレート機能:** イベントの構成をテンプレートとして保存・再利用できる。
- **過去イベント閲覧:** ログイン中のユーザーが過去に作成したイベントを一覧表示し、読み込める。
