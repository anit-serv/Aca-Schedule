# Aca-Schedule Web App 開発ドキュメント

## 1. プロジェクト概要

アカペラサークルのライブイベントにおける**本番およびリハーサル**のタイムスケジュール作成を、効率化・自動化し、ヒューマンエラーをなくすためのウェブアプリケーション。

### 主な特徴
- 直感的なUIによるタイムテーブル編集
- 複雑なイベント構成（複数日、クール分け、リハーサル）への対応
- スケジュール作成上のミスを未然に防ぐ、リアルタイム制約チェック機能

---

## 2. UI/UX 設計思想

### ワークフロー
作業フェーズを**「①バンド管理モード」**と**「②タイムテーブル編集モード」**に明確に分離する。ユーザーはまず全バンド情報を登録し、その後スケジューリングに集中する。

| モード | 目的 |
| :--- | :--- |
| **バンド管理モード** | タイムテーブル作成の「材料」となる、全てのバンド関連情報を網羅的に登録・管理する。 |
| **タイムテーブル編集モード** | 登録した情報を元に、タイムスケジュールをパズルのように組む作業に集中する。 |

### テーブル表示
- **アプリ画面上:** ヘッダー行が画面上部に追従する**「固定（スティッキー）ヘッダー」**を採用。
- **エクスポート時:** PDF/画像として出力する際は、クールやページの区切りでヘッダーが**繰り返し印刷**されるレイアウトを採用。

## 5. 機能要件定義書

### F-01: イベント管理
- **イベント作成:** ウィザード形式で「イベント名」「開催年」「会場名」「目標」などを設定する。
- **開催日設定:** カレンダーUIを使い、**本番の開催日を複数選択**できる（**連続日とは限らない**）。
- **所有者設定:** イベント作成時に、ログイン中のユーザーが自動的に所有者（ownerId）として設定される。
- **URL発行:** 作成完了後、イベント固有の編集URL（例: `/events/[ID]`）がユーザーに提示される。

### F-02: バンド管理モード
- **UI:** スプレッドシートのような一覧形式。
- **基本情報:** 「バンド名」を登録・編集できる。
- **演奏時間:** 各バンドの**演奏時間（分単位）を設定**できる。F-05で定義された「演奏時間候補」をプリセットとして利用できる。
- **出演回数:** 各バンドの出演回数を設定できる（個別・一括）。
- **メンバー:** 各バンドの出演メンバー名を入力できる（入力候補のサジェスト機能付き）。
- **出演可能時間帯:** バンドごとに、F-01で設定された各開催日および**リハーサル日**に対して、出演可能時間帯をグリッドUIで設定できる。本番とリハーサルで異なる時間帯を設定可能。

### F-03: タイムテーブル編集モード
- **UI:** 3ペイン構成。中央のワークスペースには、「本番用/リハ用」タブと、日別のタブが配置される。
- **バンドバンク:** 右ペインに、未配置バンドを一覧表示。出演回数カウンター（例: 1/2）付き。
- **ドラッグ＆ドロップ:** バンドバンクからタイムテーブルへバンドを配置・並び替えする。
- **時刻自動計算:** 全項目の開始・終了時刻をリアルタイムで自動再計算する。
- **カスタムイベント:** 「休憩」「MC」「その他」をタイムラインに挿入できる。カスタムイベントは紫色の背景で表示され、バンドバンク内で作成・削除が可能。
- **バンド番号表示:** タイムテーブルの各エントリーに通し番号（#1, #2...）を表示。制約違反メッセージにも番号を含めて分かりやすく表示。

### F-04: 構造化機能（クール）
- 各日のタイムテーブルで、その日に設ける「クール」の数を設定する。
- 設定された数の空の「クール枠」が表示され、その中にバンドを配置する。
- クール数は後からでも変更可能（0も可）。
- **クール番号は日付をまたいでも連番**となる。

### F-05: 時間設定
- バンドごとの**演奏時間はバンド管理モード(F-02)で設定**される。
- バンド間やクール間に、個別の転換時間を任意で設定できる。
- **演奏時間候補:** よく使う演奏時間を「プリセットボタン」として利用できる（定義はF-11で行う）。

### F-06: 制約チェック
- 以下の制約に違反した場合、該当行をハイライトし、アイコンとツールチップで警告する。
  1. **出演可能時間帯の超過（優先度: 高）**: バンドが設定した出演可能時間外に配置されている場合に警告
  2. **同一クール内での同一バンドの重複配置（優先度: 中）**: 同じクールに同じバンドが複数回配置されている場合に警告
  3. **出演者の連続出演（優先度: 低）**: メンバーが重複するバンドが連続して配置されている場合に警告
- **視覚的フィードバック**:
  - 違反のある行を重大度別に背景色でハイライト（赤/黄/青）
  - 行の左端にアイコン表示（🚫/⚠️/ℹ️）
  - アイコンにホバーで詳細メッセージを表示
  - バンド番号を含めた分かりやすいメッセージ（例: "バンドA (#3) の出演可能時間帯外に配置されています"）
- **制約違反サマリーパネル**:
  - 画面左端にスライド式パネルとして配置
  - 閉じた状態では小さな取っ手（警告アイコン+違反件数）のみ表示
  - クリックで展開し、重大度別に違反を一覧表示
  - パネル開閉時はスムーズなアニメーション

### F-07: カスタム項目（自由列）✅
- **実装完了✅:**
  - 項目作成時に、**「位置固定（sequence）」か「エントリー追従（entity）」かを選択**する。
  - データ入力はカスタムモードで直接入力可能。
  - タイムテーブル表示時、固定列（開始時刻、時間、名称）の右側に、**ユーザーが作成した順**で自由列が追加される。
  - セル結合（複数行マージ）機能付き（sequence 型のみ）。
  - 挿入/削除/並び替え時に自動でデータを維持・調整。
- **セル結合機能✅:**
  - sequence 型カスタム列でセルを結合可能。
  - 結合セルの自動調整: バンド挿入/削除/移動時に rowSpan マーカーを適切に更新。
  - 範囲選択 + ツールバーでセル結合/解除操作。
  - 右クリックメニューでも結合解除可能。
- **バグ修正✅:**
  - 空値でもマージ構造（rowSpan）を識別する `hasAnySequenceData()` を修正。
  - バンド移動時にマージが壊れる問題を削除+挿入アプローチで解決。

### F-08: リハーサルスケジュール管理
- **形式選択:** イベント作成時に以下の3パターンから選択（混在不可）:
  1. **別日リハーサル:** 本番とは別の日にリハーサルを実施
  2. **クール直前リハーサル:** 各バンドが本番で出演する直前にリハーサルを実施
  3. **当日一括リハーサル:** 本番当日の最初に全バンドのリハーサルをまとめて実施
- **リハーサル日設定:** 「別日リハーサル」を選択した場合、カレンダーUIからリハーサル日を複数選択できる（**非連続可**）。
- **リハーサル時間:** 全バンドで共通のリハーサル時間（分単位）を1つ設定する。各バンドで個別のリハーサル時間を設定することはできない。
- **UI:** 「タイムテーブル編集モード」内で「本番用/リハ用」をタブで切り替える。
- **編集:** 本番同様、クール分けやドラッグ＆ドロップで編集する。ただし、各バンドは1回しか配置できない。
- **リハーサルバンドの自動配置:** 
  - バンド管理画面でバンドが登録された時点で、リハーサルタイムテーブルに自動的に追加される。
  - **別日リハーサル:** 全バンドがリハーサルタイムテーブルに追加される。
  - **クール直前リハーサル:** 本番タイムテーブルに配置されたバンドのみがリハーサルタイムテーブルに追加される。本番タイムテーブルの変更を自動検知し、リハーサルタイムテーブルに即座に反映される。
  - **当日一括リハーサル:** 本番タイムテーブルに配置されたバンドのみがリハーサルタイムテーブルに追加される。リハーサルは本番と同じ日付の最初に配置される。
  - 追加後は、ドラッグ＆ドロップで自由に移動・削除が可能。

### F-09: アクセス管理✅（v2.0で実装完了）
- **ログイン認証✅:** すべての編集機能にアクセスするには、ログインが必須。
- **認証方式✅:** Googleアカウント連携による OAuth 認証。
- **イベント所有権✅:** イベントは作成者（owner）のみがアクセス・編集可能。他のユーザーはアクセス不可。
- **共有パブリックアクセス✅:** `isPublic=true` の場合、認証なしで `/share/:eventId` で読み取り専用アクセス可能。
- **セキュリティ✅:** Firestore セキュリティルールにより、バックエンドレベルでアクセス制御を実施。
- **エラーハンドリング✅:** アクセス権限がない場合やイベントが存在しない場合、どちらの理由かを明示せずに「イベントが見つかりませんでした」と表示（セキュリティのため）。

### F-10: 共有とエクスポート（部分実装✅🔲）
- **URL共有✅:**
  - `/share/:eventId` 形式の一意なシンプルなURL。セキュリティはサーバー側の `isPublic` フラグで制御。
  - イベント設定で公開/非公開を切り替え可能。
  - ヘッダーの共有ボタンから URL をコピーできる。
- **共有ページ✅:**
  - 認証なしで誰でもアクセス可能（`isPublic=true` の場合）。
  - カスタムモードの読み取り専用ビュー（CustomFieldsTable）でタイムテーブルを表示。
  - 本番/リハーサル、日付の選択が可能。
  - 編集・結合/解除・右クリックメニュー等すべての入力機能を無効化。
- **Firestore ルール設定✅:**
  - `events` / `bands` / `timetables` コレクションで `isPublic=true` の場合に未認証でも read 可能。
  - 設定手順は開発ガイドを参照。
- **注意事項:**
  - バンド名等の個人情報が含まれるためアラート表示。
  - 公開/非公開の切り替えで即座に URL のアクセス状態が変わる。
- **未実装:**
  - PDF/画像ファイルとしてのエクスポート。
  - 表示形式（シンプル/詳細）の切り替え。

### F-11: イベント設定
- **UI:** アプリ全体のヘッダーにある設定アイコン（⚙️）からモーダルウィンドウで開く。
- **編集可能な情報:** イベント名、開催年、会場、目標、本番開催日、リハーサル日、リハーサル時間、プリセット時間の設定・変更が可能。
- **読み取り専用情報:** リハーサル形式は作成後に変更できない（視覚的に区別）。
- **日付編集:** 本番開催日とリハーサル日は個別に編集可能（日付の追加・削除は不可）。日付を変更した際、既存のタイムテーブルデータは新しい日付に自動的に引き継がれる。
- **プリセット時間設定:** そのイベントでよく使う演奏時間をユーザーが自由に設定・変更できる。
- **カスタム項目定義:** F-07で利用するカスタム項目（自由列）の定義（名称、種類）を管理する。

### F-12: 長期利用向け機能✅（v2.0で一部実装完了）
- **ログイン機能✅:** ユーザーアカウントを作成し、個人のデータを安全に管理する。Google OAuth 認証に対応。
- **マイイベント一覧✅:** ログイン中のユーザーが作成したイベントを一覧表示し、簡単にアクセスできる。
- **イベント所有権管理✅:** 各イベントに所有者（ownerId）を設定し、作成者のみがアクセス・編集可能。
- **テンプレート機能🔲:** イベントの構成をテンプレートとして保存・再利用できる（未実装）。
- **高度な設定✅:** カスタム項目の定義・管理機能を実装。プリセット時間設定も実装済み。

## 6. ユーザー向けBand API（UIと併用）

認証済みユーザー本人が、UIに加えてAPI経由でもバンドを登録できるようにしました。

### エンドポイント
- `POST /api/v1/bands`
- `POST /api/v1/user-api-tokens`（APIトークン発行）
- `GET /api/v1/user-api-tokens`（APIトークン一覧）
- `PATCH /api/v1/user-api-tokens?tokenId=...`（APIトークン更新）
- `DELETE /api/v1/user-api-tokens?tokenId=...`（APIトークン失効）

### 認証方式
`POST /api/v1/bands` は次のどちらかで認証します。

1. Firebase IDトークン（推奨）
  - `Authorization: Bearer <Firebase ID Token>`
2. ユーザー発行APIトークン（自動化向け）
  - `x-user-api-token: <pat_...>`

さらに冪等性のため次のヘッダが必須です。

- `x-idempotency-key`（1-64文字）

`user-api-tokens` の管理APIは Firebase IDトークンのみ利用できます。

### リクエストボディ（要点）
- `eventId`: 必須
- `name`: 必須
- `performanceDuration`: 必須（1-180）
- `performanceCount`: 任意（1-10、デフォルト1）
- `members`: 任意（最大30件）
- `availableTimeSlots`: 任意

`availableTimeSlots` の時刻は `HH:mm` 形式で、分は `00` または `30` のみ許可されます。

### 主なレスポンス
- `201`: 作成成功
- `200`: 冪等再送（同一内容の再送）
- `400`: 入力不正
- `401`: 認証失敗（IDトークン無効 / APIトークン失効・期限切れ）
- `403`: eventId の権限不足（オーナー/共同編集者でない、またはAPIトークンスコープ外）
- `409`: 冪等キー競合
- `429`: レート制限超過

### Vercel環境変数
Vercel Project Settings > Environment Variables に以下を設定してください。

- `FIREBASE_SERVICE_ACCOUNT_JSON`
  - Firebase Admin SDK のサービスアカウントJSON全文
- `FIREBASE_PROJECT_ID`
  - FirebaseプロジェクトID（省略時はJSONの `project_id` を利用）

### Firestore追加コレクション
API運用のため、以下のコレクションを使用します。

- `userApiTokens`: ユーザー発行APIトークン管理（ハッシュ保存）
  - `userId`, `userEmail`, `name`
  - `tokenHash`（平文は保存しない）
  - `allowedEventIds`: 書き込み許可eventId配列
  - `status`: `active` / `revoked`
  - `expiresAt`, `lastUsedAt`, `rateLimitPolicy`
- `apiIdempotency`: 冪等制御
- `apiRateLimits`: レート制限カウンタ
- `apiRequests`: 監査ログ

### 補足
- `vercel.json` は `/api/*` をSPA rewriteより先に評価する設定に変更済みです。
- このAPIはサーバ側（Firebase Admin SDK）で書き込むため、Firestoreルールは既存UI用途として維持されます。

### ローカル検証スクリプト
新しい認証フロー（Firebase IDトークンでPAT発行 -> PATでBand作成）をまとめて試すには、ルートの `test-api-user.cjs` を使います。

```bash
FIREBASE_ID_TOKEN=<Firebase ID Token> node test-api-user.cjs
```

任意で次の環境変数を指定できます。

- `BASE_URL`（既定: 現在のVercel URL）
- `EVENT_ID`（既定: `event-1`）
